TOOL VS SYSTEM RULE

- Same type of work: SQL, ETL, data movement, validation
- These roles can be APPLY NOW

SYSTEM / PLATFORM DIFFERENCE, higher risk:
- Example: AWS modernization, DataOps platform, multi-system architecture ownership
- Involves environment ownership, platform transitions, or cross-system design
- These roles should usually be downgraded to OPTIONAL / STRETCH or SKIP
- Usually conditional or risky

Prefer roles where the work is familiar even if the tool is different.
Avoid roles where the system/platform context is the main job.
